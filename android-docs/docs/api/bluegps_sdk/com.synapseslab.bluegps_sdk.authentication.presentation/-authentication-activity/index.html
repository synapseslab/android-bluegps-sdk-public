AuthenticationActivity

class AuthenticationActivity

Internal activity that handles the OAuth 2.0 + PKCE authentication flow for BlueGPS.

This activity is not meant to be launched directly. Instead, use the provided ActivityResultContract wrappers:

  • AuthLoginActivity for the login flow

  • AuthLogoutActivity for the logout flow

Security model

The redirect URI uses an HTTPS App Link (verified via /.well-known/assetlinks.json) instead of a custom URI scheme. This prevents authorization code hijacking: only the app whose SHA-256 certificate fingerprint is listed in assetlinks.json can receive the redirect intent. PKCE (RFC 7636, S256) is applied on every login as an additional layer of defense — the authorization code is useless to an interceptor without the matching code_verifier.

The consuming app must declare authRedirectHost as a manifest placeholder in its build.gradle flavor config so the SDK manifest can resolve the App Link host at build time.

Why the activity is declared singleTask

The callback has to reach the very instance the integrator started for result, otherwise its setResult goes to whoever launched it — the browser — and the integrator's launcher only ever sees RESULT_CANCELED. Since Custom Tabs runs in the caller's task, the top of the task during the flow is the browser, so a singleTop declaration let the system spin up a second instance for the callback: it exchanged the code and persisted the session while the original instance reported a cancellation, and the login appeared to fail although it had succeeded. See the manifest for the full rationale.

Login flow

  1. Generates a PKCE code verifier/challenge pair.

  2. Opens the authorization URL in a browser (Chrome Custom Tabs if available, otherwise the system default).

  3. Receives the redirect with the authorization code via onNewIntent.

  4. Exchanges the code for tokens via AuthenticationViewModel.

  5. Returns android.app.Activity.RESULT_OK with a com.synapseslab.bluegps_sdk.authentication.data.models.KeyCloakAuthResponse on success, or android.app.Activity.RESULT_CANCELED if the user cancels or an error occurs.

Error handling

If no browser is installed on the device, the activity finishes with android.app.Activity.RESULT_CANCELED and attaches EXTRA_ERROR_REASON = ERROR_NO_BROWSER to the result Intent, so the integrator can distinguish a missing-browser error from a deliberate user cancellation.

Usage example

// Register the launcher once (e.g. in Fragment.onCreate or as a property)
private val loginLauncher = registerForActivityResult(AuthLoginActivity()) { response ->
    if (response != null) {
        // Login succeeded — response contains the access/refresh tokens
    } else {
        // Login failed or cancelled — check why
        val reason = lastCanceledIntent?.getStringExtra(AuthenticationActivity.EXTRA_ERROR_REASON)
        if (reason == AuthenticationActivity.ERROR_NO_BROWSER) {
            showError("No web browser is installed on this device.")
        } else {
            // User pressed back or dismissed the browser
        }
    }
}

// Trigger login (useCustomTabs = true by default)
loginLauncher.launch(AuthLoginInput())

// Trigger logout
private val logoutLauncher = registerForActivityResult(AuthLogoutActivity()) { result ->
    if (result != null) {
        // Logout succeeded
    }
}
logoutLauncher.launch(AuthLogoutActivity.LAUNCH_MODE)
