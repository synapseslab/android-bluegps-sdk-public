instantChargeEvents

fun BlueGPSLib.instantChargeEvents(): Flow<InstantChargeEvent>

Observes the instant charging state of the user, the channel of the screen.

The stream starts from a status read, then follows the WebSocket of the user: assignment from the queue, queue position, phase changes, hold expiry, the snooze after a decline and the closing of the pool all arrive here as InstantChargeEvent.StatusUpdate, the same object of getInstantStatus that replaces the state on screen.

Recovery is handled by the SDK: any end of the socket, an expired uuid included, starts again from the status read, and a slow safety read every 60 seconds notices a socket that died in silence. The channel lives as long as the collection: bind it to the visible lifecycle of the screen and the return in foreground restarts it from the status, as it has to.

The stream completes with InstantChargeEvent.Disabled when instant charging is switched off; a failed read is reported as InstantChargeEvent.StatusUnavailable and retried with a backoff.
