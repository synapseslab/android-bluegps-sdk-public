start

abstract fun <C> start(channel: IndicatorChannel, initial: C, updates: Flow<C> = emptyFlow(), render: <Error class: unknown class>.(C) -> Unit): Boolean

Starts the session and shows its notification at once, drawn by render with initial. Call it with the app in the foreground: from the background the indicator is IndicatorState.Unavailable with UnavailableReason.REQUEST_FAILED and the session runs without it.

Each value of updates replaces the content. A value equal to the one shown is skipped; at most one update per second reaches the notification, the newest winning. updates must live as long as the session: a flow tied to a screen (stateIn(viewModelScope)) stops with the screen and freezes the notification on its last value.

render runs on the main thread, synchronously, at every update. The SDK has already set the channel, the ongoing flag, setOnlyAlertOnce and the delete intent, and sets them again after render: everything else, small icon included, is the app's. InboxStyle prevents the promotion to a Live Update on Android 16. If render(initial) throws, the service does not start and the indicator is UnavailableReason.REQUEST_FAILED; a later failing render leaves the previous notification.

Never throws: what is missing is reported in limitations and indicator.

Return

false, changing nothing, when a session already runs.
