BlueGPSAuthDiagnostics

object BlueGPSAuthDiagnostics

Optional hook that reports how the interactive login flow actually unfolded.

The browser callback is the one step of the flow an integrator cannot observe: it is handled inside the SDK, in an Activity the app never touches, and by the time the app hears about it all that is left is a result code. When the callback goes wrong the app therefore sees the same "no result" for a redirect that never arrived, a code that was rejected, a state that did not match and a token exchange that failed — four different problems with four different remedies. On the environments where this matters (a host reachable only through a corporate VPN, devices that cannot be attached to a debugger, release builds where R8 has stripped every android.util.Log call) there is no other way to tell them apart.

Set sink and the SDK will report each step. Nothing is recorded unless a sink is set, and the SDK never logs the events itself.

What is reported

Enum-like names, booleans and numbers only — never a token, an authorization code, a verifier or a URL. In particular the identity provider's error text is deliberately NOT reported: it is free text nobody here controls, and it can carry a URL or echo the request back. What replaces it says as much without that risk — an HTTP status distinguishes a rejected code from a server fault, an exception class name distinguishes an unreachable endpoint. The payload is therefore safe to persist and to keep enabled in a release build.

instance=new is the interesting one: it means the callback did not reach the Activity the integrator started for result, which is the shape of the failure fixed in 6.2.9.
